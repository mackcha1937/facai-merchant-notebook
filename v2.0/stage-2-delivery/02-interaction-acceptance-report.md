# 02 · 阶段2交互验收报告

版本：v2.0-rc1 阶段2
归档日期：2026-08-23
验收对象：`1cac323`

## 1. 验收方式

- 审阅阶段2前端源码、ContextStack逻辑和自动测试；
- 使用正式构建产物在真实Chromium中检查1280×800桌面视口；
- 使用正式构建产物在真实Chromium中检查390×844手机视口；
- 验证进入、显式返回、关闭、收起、浏览器返回、草稿和列表状态恢复；
- 所有操作仅作用于Mock前端状态，没有提交真实账本数据。

## 2. 手机端

### 已形成闭环

- 顶部在对话和覆盖工作区固定显示；
- 今日事项数字表示未处理数，“新”表示仍有未查看事项；
- 打开今日事项总列表不会一次清除全部未读；
- 逐条打开只改变该事项的已读状态，不改变未处理数；
- 点击处理后未处理数下降；
- 左侧抽屉只有对话、全部客户、管理与设置三个一级入口；
- 点击遮罩可以关闭抽屉，输入草稿不丢失；
- 全部客户可搜索化名或别名；
- 客户索引→客户档案→服务详情可通过页面按钮逐层返回；
- 返回客户索引后搜索词保留；
- 返回对话后未发送草稿保留；
- 客户、今日事项和管理工作区在手机宽度下以固定覆盖层显示。

### 尚未形成闭环

- 抽屉没有实现左滑关闭；
- 抽屉打开后没有完整的焦点陷阱；
- 关闭工作区或抽屉后，没有完整的显式焦点恢复实现和集成测试；
- 聊天中的CustomerRecordCard没有可用的“收起档案”操作；
- 聊天演示流中部分嵌入Block使用空回调，只用于展示，不能当作完整业务交互；
- 页面刷新后Mock事项和ContextStack状态不会持久化。

## 3. Web端

### 已形成闭环

- 固定左栏提供对话、全部客户、管理与设置；
- 中间主对话持续存在；
- 客户、今日事项和管理详情在右侧工作区打开；
- 客户搜索后进入档案、进入服务详情、逐层返回，可恢复搜索词；
- 主对话中的未发送草稿在打开和关闭右侧工作区后保留；
- ReceiptCard成功状态支持展开和收起；
- 管理与设置详情均提供返回上一级入口。

### 尚未形成闭环

- 内部视图切换没有同步更新可恢复URL；
- 从 `/app/customers` 或 `/app/manage` 返回对话后，地址栏仍可能保留原入口路径；
- 页面刷新会根据入口路由重新建立初始视图，而不是恢复当时ContextStack；
- 右侧CustomerRecordCard本身没有通用收起按钮；
- Web工作区关闭后的焦点恢复没有完整实现。

## 4. 浏览器/系统返回键

结论：未达到阶段2规范所要求的“与页面返回按钮一致”。

源码中的内部 `pushView` 只修改内存ContextStack，没有对应执行 `history.pushState`。
仓库虽然存在 `useContextStack.js` 中的history处理逻辑，但当前AppShell没有使用该Hook，而是维护了另一套返回逻辑。

真实浏览器验证观察到：

- 直接打开应用、浏览历史长度为1时，从服务详情执行浏览器返回不会退回客户档案；
- 存在先前浏览历史时，浏览器会先改变URL，再由页面尝试处理内部状态，可能出现URL与当前上下文不一致；
- 因此不能把“浏览器返回键行为一致”记录为已通过。

阶段3开始前应统一ContextStack、React Router和浏览器history的状态来源，并增加真实AppShell集成测试。
