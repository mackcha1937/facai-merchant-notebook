# 03 · 产品实体与匹配报告

## 1. 实体模型

`Product` 已具备 owner 边界、规范名、品牌、分类、规格、生命周期、知识状态、版本、软删除和合并去向。`ProductAlias` 保留原始别名和归一化别名，查询和唯一性均限定在 tenant/owner 边界内。

## 2. 匹配顺序

已配置模型时，DeepSeek 只提取产品名、品牌、规格、数量、原文证据和置信度，不接收或生成可信产品 ID。校验通过后，后端再在当前 tenant/owner 的权威产品集合中执行以下匹配：

产品数量不信任模型数字。后端会从 `evidence_text` 确定性解析中文或阿拉伯数字数量，并要求与模型值一致；不一致时丢弃整个模型结果并使用后端原文规则。例如“买了面霜一瓶”不可被模型改为 999 瓶。

1. 规范名精确匹配；
2. 别名精确匹配；
3. Unicode 归一化后的模糊字符匹配；
4. 本地 96 维名称字符特征余弦候选。

接口最多返回 3 个候选，并明确标记 `exact`、`fuzzy`、`ambiguous`、`not_found` 或 `insufficient`。本地特征只用于产品名称消歧，`rag_used=false`，不保存 EmbeddingRecord，不读取知识片段。

## 3. 新建、购买与合并

- 新产品以 `draft/incomplete` 建立，品牌或规格缺失时在确认卡明示；
- 未识别产品的购买先进入 ProductMatchCard，选择后再进入唯一 ConfirmCard；
- 选择“作为新产品”后，产品草稿和购买 LedgerEntry 在同一事务中创建；
- 事务中任意事实或产品动作失败时，产品、购买和事实整体回滚；
- 合并时将购买关联和可用别名移至目标产品，源产品标记 `replaced` 并保留 `merged_into_id`；
- 旧版 `product_name` 文本字段保留，不破坏 V1 历史账本展示。

## 4. 幂等与并发

产品选择、确认和语音命令都携带幂等键。重试返回原 Proposal/原结果，不会重复创建产品或购买记录。产品状态或版本在确认期间变化时，返回可恢复冲突而不强制写入。
