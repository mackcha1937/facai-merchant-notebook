# 02 · 客户事实报告

## 1. 候选与确认

- 事实候选包含 `fact_type`、展示值、归一化值、原文证据、置信度和敏感级别；
- 受控规则覆盖肤质敏感、痘痘倾向、成分不耐受、营销偏好、联系偏好、普通偏好、生日和低置信观察；
- 已配置模型时，V2 主对话会实际调用 Adapter；只有通过严格 JSON Schema、枚举、长度、类型、原文证据、置信度和提示注入校验的候选才能进入 Proposal；
- 无模型、超时、网络失败或输出不合法时回退到保守规则，不使用部分失败的模型结果；
- 只有 `confirmed` 且当前有效的事实进入客户权威读模型；
- 敏感事实在 ConfirmCard 中单独分组，店主可勾选移除后再确认。

## 2. 冲突、版本和撤销

同一客户、同一事实类型的新值会显示与当前值的冲突。确认后，旧记录关闭有效期，新记录通过 `supersedes_id`、`superseded_by_id` 和版本号串联。店主删除事实时，系统先生成待确认撤销动作；确认后关闭当前记录，并保留撤销审计记录。

## 3. 测试覆盖

- 确认前零写入；
- 多事实抽取、成分不耐受、低置信观察；
- 敏感候选通过文本/语音命令移除；
- 同类型新值覆盖时的版本链；
- 删除在确认前不生效，确认后保留撤销记录；
- 租户/店主边界与事务回滚。
