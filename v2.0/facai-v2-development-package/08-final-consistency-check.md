# V2 开发包一致性检查

检查日期：2026-08-21  
结论：已具备交给 VS Code 开发Agent执行阶段0的材料；尚不等于可以直接上线。

## 1. 已覆盖的产品闭环

- 文字/语音录入、修改、确认、取消、撤销和结果查询共用同一业务流程；
- 核销后返回绝对日期、累计使用/总次数和剩余次数；一次性服务使用简化回执；
- 客户精确、别名、近似Top3、无客户新增确认；
- 历史未知产品/服务识别、候选、确认入库、知识补充和RAG索引状态；
- 手机顶部今日事项和未读红点；左侧仅保留对话、全部客户、管理与设置；
- 全部客户、客户二级详情、产品/服务详情、管理设置均有进入、处理、失败、取消和逐层返回；
- 客户完整记录在对话工作区可展开/收起，返回恢复滚动、筛选和输入草稿；
- Web固定左导航、主对话、右上下文工作区；手机和Web共享线程、账本与阅读状态；
- 多日主线程、按日Session、摘要、PendingAction过期和数据库事实优先；
- 推荐候选、硬排除、评分、RAG证据、店主话术、稍后和反馈；
- 店主AI状态只读，管理员独立控制模型、提示词、RAG、推荐、测评、发布和回滚。

## 2. 已覆盖的技术与安全闭环

- tenant级数据隔离、owner/admin RBAC、密钥服务端保存、日志脱敏、审计和备份恢复；
- Proposal二次确认、事务、幂等、余额并发保护、软删除和反向恢复记录；
- SpeechToText、ChatModel、Embedding独立Adapter；
- 客户权威数据保留在SQL，知识文档进入向量索引，推荐使用混合检索；
- 知识确认、版本、checksum、切分、Embedding、索引、过滤、取证、生成、反馈、重建完整流程；
- 模型、Embedding、RAG、网络和调度失败的降级路径；
- 禁止诊断、治疗/治愈承诺、提示注入、跨店泄漏和店主越权修改AI配置。

## 4. 开发阶段0必须验证的未决项

1. 用户提供的 `deepseek-v4-pro` 是否为当前API账户真实可用模型ID；不能只按名称写死。
2. DeepSeek当前账户对结构化输出、流式响应、超时和限流的真实表现。
3. SpeechToText供应方、本地浏览器兼容性、中文店名/昵称/项目名识别率和费用。
4. Embedding供应方、向量维度、中文召回效果、价格和是否允许发送匿名化知识。
5. 现有V1项目真实技术栈、数据库位置、Migration能力和启动命令。
6. 进入多端测试前的远程数据库、认证、HTTPS、对象存储和备份方案。

这些是需要真实环境验证的工程决策，不应由文档假装确定；它们已经被放入阶段0停点，不妨碍现在把开发包交给VS Code。
