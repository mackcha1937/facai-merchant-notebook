# 前端开发文档：发财 V2 双端交互

版本：v2.0-rc1  
状态：开发交接候选版·待用户最终确认  
日期：2026-08-21

## 1. 设计目标

前端表面简单、能力完整：一个持续对话承载高频业务；客户、产品和推荐使用固定、可收起、可返回的上下文组件；批量管理进入低频工作区。所有手工业务都能由语音发起和调整。

## 2. 硬性交互规则

1. 一次店主输入最多一次最终写入确认；
2. 每张卡最多一个主按钮和两个辅助按钮；
3. 日常业务不使用居中弹窗；
4. 查看、返回、收起、取消、完成、失败和重试必须有闭环；
5. 返回后恢复来源、滚动、筛选、草稿和未确认状态；
6. 可手动操作的业务必须可由文字或语音等价完成；
7. 语音转写文本先可见、可改，再进入解析；
8. 查看/展开/返回不产生无意义聊天消息；
9. 浏览型卡片重新展开读取最新权威数据；回执保留当时结果；
10. AI不得生成任意HTML，只能返回固定UI Block数据。

## 3. 手机H5与微信WebView

### 3.1 顶部

```text
☰  发财                         今日事项 4 🔴
```

- 菜单始终可见；
- 今日事项数字表示未处理总数；
- 红点表示至少一条未查看；
- 顶部在对话、客户索引和管理工作区都固定；
- 点击今日事项保存当前上下文并在主工作区展开事项卡。

### 3.2 左侧抽屉

一级仅包含：

```text
对话
全部客户
管理与设置
```

- 抽屉宽度约80%，最大320px；
- 点击遮罩、左滑、菜单按钮或系统返回键关闭；
- 关闭不丢失对话位置和输入草稿；
- 管理与设置内部使用第二层分组，不在一级铺开低频功能。

### 3.3 对话区

- 日期分隔；
- 店主消息、AI文本、固定卡片和回执；
- 支持按需加载较早历史；
- 跨日未完成以系统卡展示，不自动写入；
- 新的一天回到主对话根层级，不恢复深层展开，但提供“继续昨日事项”。

### 3.4 输入区

- 文本、语音、发送；
- 语音转写中有明确状态和取消；
- 转写后文本进入同一输入框；
- 店主可以说“确认”“取消”“日期改昨天”“返回客户列表”等；
- 网络失败保留草稿；
- 请求期间防重复提交并允许停止生成。

## 4. 电脑Web店主端

```text
左侧导航（固定）｜主对话（核心）｜右侧上下文工作区（可收起）
```

### 4.1 左侧

- 对话；
- 全部客户；
- 管理与设置；
- 不展示AI技术编辑入口。

### 4.2 中间

- 与手机同一个Thread和Message；
- 保留顶部今日事项；
- 所有写入确认仍在对话中完成；
- 右侧打开不会让中间滚动跳动。

### 4.3 右侧工作区

- 客户档案、产品、服务、推荐依据、管理详情；
- 顶部显示上下文返回路径；
- 关闭后焦点回到来源消息；
- 只保存每台设备的展开状态，不同步宽度和滚动。

## 5. 固定UI Block

### 5.1 ConfirmCard

用途：所有待写入Proposal。

必须包含：变化摘要、绝对日期、权威预检查、证据/原始表达、一个主确认按钮和修改入口。多项操作合并展示；店主可用语音修改。

### 5.2 CustomerRecordCard

默认分区：概况、事实、服务套餐、产品、跟进、账本历史。支持收起、返回来源、分区筛选和历史分页。完整数据由后端读模型提供，不由大模型生成。

### 5.3 ProductMatchCard

状态：exact、fuzzy、ambiguous、not_found、insufficient。单一近似时显示一个；多候选最多三个；新产品显示已识别字段、缺失字段和“资料待补充”影响。

### 5.4 RecommendationCard

展示：客户、推荐对象、为什么现在、主要证据、不确定性、话术。默认按钮为“复制话术”和“换一句”。稍后、不合适等可通过自然语言或折叠辅助操作完成。

### 5.5 FeedbackCard

展示从客户回复提取的事实、状态和下次绝对提醒日期；明确哪些将更新、哪些仅保存为备注；确认后刷新推荐和客户档案。

### 5.6 ReceiptCard

成功、失败、取消、冲突、已删除/已恢复。成功后压缩；失败在原位置重试；历史回执保留当时结果并可查看当前状态。

### 5.7 TodayTaskCard

按建议跟进、待确认、资料待补充和冲突分组。打开列表不批量清除红点；逐条成功打开后更新read_at。查看不等于处理。

### 5.8 CustomerIndexCard

全部客户、搜索、全部/待跟进/有待确认资料、最近消费/最近更新排序。点击客户保存query/filter/sort/scroll，再展开客户档案；返回完整恢复。

## 6. 上下文栈与返回

```ts
type ViewContext = {
  viewType: string;
  originType: "chat" | "today" | "customer_index" | "management";
  originMessageId?: string;
  parentBlockId?: string;
  query?: string;
  filters?: Record<string, string>;
  sort?: string;
  scrollPosition: number;
  draftInput: string;
};
```

返回顺序：详情第二层→详情第一层→客户索引/今日事项→对话→关闭抽屉→允许离开应用。系统/浏览器返回键遵循相同规则。

未保存修改使用卡片内提示：保存草稿、放弃并返回；不得静默丢失或弹居中框。

## 7. 今日事项和红点

- `unresolved_count`驱动数字；
- `unread_count > 0`驱动红点；
- 每项保存read_at、handled_at、status、updated_at；
- 事项更新后重新未读；
- 客户列表行聚合该客户未读事项；
- 手机和Web同步阅读与处理状态；
- 红点同时有“新”文本/无障碍标签。

## 8. 全部客户闭环

```text
左侧全部客户
→ 搜索/筛选/排序
→ 点击客户
→ 对话或右侧展开档案
→ 产品/服务详情
→ 返回档案
→ 返回列表并恢复状态
→ 返回对话
```

新增、编辑、合并、删除均通过聊天内Proposal确认。删除展示关联影响并进入回收站；合并展示差异、冲突和保留项。

## 9. 管理与设置闭环

### 9.1 店主端分组

```text
产品与服务
数据管理
账号与安全
AI运行状态（只读）
```

每个分组最多三层。操作从哪里来就回哪里；例如从小红档案补产品资料，成功后先回产品，再回小红，不统一扔到产品库首页。

### 9.2 产品与服务

索引→详情→编辑/语音调整→确认→回执→详情→索引。资料待补充、待确认、停用、相似待合并和RAG索引状态明确。

### 9.3 数据管理

导入：选文件→预览→重复/错误→修改或排除→确认→事务写入→结果→失败行。  
导出：选范围→生成→下载→返回。  
恢复：查看影响→恢复前备份→确认→重建读模型/索引→结果。

### 9.4 AI运行状态

只读展示对话模型、Embedding、RAG、推荐、测评、最近检查和知识覆盖。无输入、开关、保存和密钥。允许从来源提交AI错误反馈，成功后返回来源。

## 11. 页面状态

所有工作区必须有：初始、加载、空、成功、校验失败、网络失败、模型失败、权限失败、数据冲突、已过期和降级状态。

- Skeleton代替整页Spinner；
- AI文本可流式，权威卡片在完整校验后出现；
- 错误与重试留在原卡片；
- 离线只保留草稿，不伪造成功；
- 模型失败提供人工入口和模板结果。

## 12. 前端数据与缓存

- 服务器状态使用请求缓存；
- 聊天流、ContextStack、输入草稿和设备UI状态分开；
- 确认写入后按后端返回刷新相关customer/product/recommendation keys；
- 不使用前端计算作为最终余额；
- 列表虚拟化，历史分页；
- 同一Proposal按钮携带幂等键；
- SSE断线可按message/event id续传或回退重试。

## 13. 路由建议

店主端可使用同一应用壳：

```text
/app/chat
/app/customers（恢复CustomerIndex状态）
/app/manage
```

详情主要以Block/工作区状态表达；Web可用可恢复URL，手机不强制多页面。管理员端独立 `/admin/*`，RBAC校验后加载。

## 14. 前端验收模板

每项必须回答：入口、展示、主操作、语音等价、修改、取消、成功、失败、重试、返回、状态保留、跨天、跨设备、AI降级和权限。
