## 2. 唯一开发基线

- V2在V1准确账本能力上增加客户事实、产品实体识别、时间触发、混合推荐、RAG、话术、反馈闭环、多日对话和双端同步；
- 高频业务以对话完成，低频管理保留明确入口；
- 所有可手动完成的业务操作，都必须支持店主通过文字或语音发起、修改、确认、取消和查询结果；
- 语音先转文字，后续意图、校验、确认规则与文字完全一致；
- 手机顶部固定“今日事项数量＋未查看红点”；左侧只放“对话、全部客户、管理与设置”；
- 店主只能查看AI运行状态，不能修改模型、提示词、RAG参数、推荐权重和测评发布；
- 产品管理员使用独立管理员Web控制台；
- 所有写操作都由后端生成Proposal，店主确认后以单个事务写入；
- AI、RAG或网络失败时，基础账本和人工管理仍可使用；
- 所有客户、产品、服务、推荐和聊天数据均使用虚构样例，不得把本包内容当作真实美容或医疗建议。

## 3. 技术建议

沿用V1技术栈并逐步升级，不重写已有可用模块：

```text
前端：React + TypeScript + 响应式单应用壳
后端：FastAPI + 分层领域服务
本地测试数据库：SQLite
远程多端数据库：PostgreSQL（进入公开测试前迁移）
对话模型：DeepSeek适配器
Embedding：独立可替换适配器
RAG：结构化SQL检索 + 关键词/模糊匹配 + 向量检索
流式响应：SSE
定时检查：本地启动时/每日一次；远程阶段使用服务端调度
```

## 4. 开发治理

- 严格按 `07-development-roadmap-vscode-handoff.md` 分阶段；
- 每阶段完成后提供手机和电脑临时验证地址、自动测试结果、手工验收步骤并暂停；
- 任何模型、提示词、知识或推荐策略的正式发布，都必须先通过测评门槛；
- 现有V1数据迁移前必须备份，禁止重置或覆盖用户数据库；
- 未经用户最终确认，不得把v2.0-rc1标记为正式生产版本。
