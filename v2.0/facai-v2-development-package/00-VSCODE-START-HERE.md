# 给 VS Code 的起点

版本：v2.0-rc1  
状态：开发交接可用；生产发布仍需逐阶段验收  
日期：2026-08-21

## 你要做什么

1. 把整个 `facai-v2-development-package` 文件夹放进现有“发财”项目根目录，保留原目录结构。
2. 用 VS Code 打开“现有发财代码所在的项目根目录”，不是只打开某一个Markdown文件。
3. 确认代码和数据库已有备份，API Key仅放在本机 `.env`，不要粘贴进聊天、截图或代码。
4. 把下面的指令完整交给 VS Code 中的开发Agent。
5. 它完成阶段0后必须停下。你先看差异、风险、模型验证和临时验证地址，再回复“阶段0确认通过”。

## 第一条开发指令

```text
你现在负责“发财·智能客户经营助手 V2”的分阶段开发。

先完整阅读 facai-v2-development-package 中的 README、00、01～08号文档、contracts、data、prompts、eval，以及现有项目代码、数据库Schema、迁移和测试。需求冲突时按以下顺序处理：
1. 数据安全、权限、禁止医疗宣称和确认写入规则；
2. 01-product-requirements.md；
3. 02-frontend-interaction-spec.md 与 03-backend-architecture.md；
4. 其余专项文档和机器可读协议。

重要约束：
- 不删除、重置、覆盖V1数据或用户已有代码；先备份并输出差异；
- 本轮只做阶段0，不实现阶段1及以后；
- 先确认现有技术栈、启动方式、数据库路径和DeepSeek真实可用模型ID；
- deepseek-v4-pro只是用户提供的目标名称，必须通过官方接口实际验证，不得假装调用成功；
- SpeechToText和Embedding都使用独立Adapter，阶段0只验证候选方案和接口，不替用户擅自购买服务；
- API Key只能从服务端环境变量读取，不得输出到前端、日志、错误或文档；
- 所有可手动业务操作都必须能用文字或语音等价完成，但语音先显示可编辑转写，不能绕过Proposal和二次确认；
- 店主只能查看AI状态；AI模型、提示词、RAG、阈值和发布只能由管理员在独立Web控制台管理；
- 每个阶段完成后给手机端、电脑Web端、管理员端（如适用）的临时验证地址、测试结果、已知限制和验收步骤，然后停下等待确认。

阶段0交付：
1. 现有代码和V1能力清单；
2. V2需求差异矩阵；
3. 数据库与迁移风险；
4. DeepSeek模型、结构化输出、超时、错误处理的真实验证结果；
5. SpeechToText与Embedding Adapter候选和取舍，不接真实客户数据；
6. 本地运行、测试、备份和回滚命令；
7. 阶段1实施计划；
8. /verify/v2-stage-0 临时验证地址。

完成后明确写：“阶段0已完成并暂停，等待用户确认。”
```

## 不要一次性让它做完

本项目涉及账本余额、客户隐私、AI建议和跨天状态。逐阶段暂停能让你在每一步检查方向，也能避免AI擅自重写旧数据。完整阶段见 `07-development-roadmap-vscode-handoff.md`。
